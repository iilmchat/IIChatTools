#	Правило	Требование
1	Комментарии	Русский язык, включая XML-документацию
2	XML-doc	Обязательна для всех public классов, интерфейсов, методов, свойств. Теги: <summary>, <param>, <returns>, <exception>
3	Именование	Публичные члены — PascalCase; приватные поля — _camelCase; локальные — camelCase
4	DI	Только через конструктор, без ServiceLocator
5	Async	Все I/O-методы — с суффиксом Async
6	Исключения	Контроллеры: try-catch → { success, data, message }. Сервисы: throw с осмысленным сообщением
7	Логирование	ILogger — техника; IAuditService — действия пользователей
8	Безопасность	Пути — PathHelper.TryGetSafeFullPath; CLI — ArgumentList; лимиты размеров
9	Версионирование	AppVersion.Current при изменении API
10	Known Issues	Любая найденная проблема, ограничение или наблюдение — фиксируется в docs/KNOWN_ISSUES.md с уникальным номером KI-XXX, приоритетом, статусом и файлами. Даже если это «не баг» — запись нужна для истории.
11	Локализация	Новые UI-строки — в оба файла .resx (RU+EN); синхронизация проверяется тестом LocalizationSyncTests
12	Инструменты	Новый инструмент = 1 класс + 1 строка регистрации в Startup.cs в соответствующей группе; параметры описываются через ToolParameterDescriptor

# Известные проблемы IIChatTools

Файл ведётся с версии 1.0 (сентябрь 2026).
Формат: `KI-XXX` — название, приоритет, статус, файлы.

## Исправленные

### KI-002 — 407 Proxy Authentication Required для веб-инструментов
- **Приоритет:** 🔴 Critical | **Статус:** Fixed | **Исправлено в:** v1.0.2
- **Файлы:** `IIChatTools.API/Startup.cs`
- **Решение:** `HttpClientFactoryOptions.HttpMessageHandlerBuilderActions` + `WebProxy.Credentials`.

### KI-003 — 403 Forbidden от Wikipedia API
- **Приоритет:** 🟠 High | **Статус:** Fixed | **Исправлено в:** v1.0.2
- **Файлы:** `WikipediaSearchTool.cs`
- **Решение:** User-Agent `IIChatTools/1.0 (https://github.com/RuChating/IIChatTools; iilmchat@localhost)`.

### KI-004 — Git-инструменты не поддерживали подкаталоги
- **Приоритет:** 🔴 Critical | **Статус:** Fixed | **Исправлено в:** v1.0.2
- **Файлы:** `BaseGitTool.cs` + 7 `Git*Tool.cs`
- **Решение:** Параметр `path` + `GitContextValidationResult` + `RunGitInDirAsync`.
- **API-изменения:** `git_diff.path` → `filePath`; `git_log.path` → `filePath`; `git_add.paths` → `files`; `git_checkout.paths` → `files`.

### KI-006 — gh-инструменты не поддерживали подкаталоги
- **Приоритет:** 🔴 Critical | **Статус:** Fixed | **Исправлено в:** v1.0.2
- **Файлы:** `BaseGhTool.cs` + 6 `Gh*Tool.cs`
- **Решение:** Параметр `path` + `GhContextValidationResult` + `RunGhInDirAsync`.

## Документированные (не баги)

### KI-001 — Неинформативное сообщение при отклонении действия
- **Приоритет:** 🟡 Medium | **Статус:** Open | **Запланировано:** v1.0.3
- **Файлы:** `test.js`, `approvals.js`
- **Решение:** Показывать причину отклонения в поле «Результат».

### KI-005 — Неявный `git add -A` при пустом списке файлов
- **Приоритет:** 🟠 High | **Статус:** Documented
- **Файлы:** `GitAddTool.cs`
- **Причина:** Пустой `files` трактуется как `-A`. Документировано в описании инструмента.

### KI-007 — gh issue create требует заранее созданные метки
- **Приоритет:** 🟢 Low | **Статус:** Documented
- **Причина:** Ограничение `gh` CLI. Метки должны быть созданы заранее.

### KI-008 — Хрупкость git-истории при манипуляциях
- **Приоритет:** 🟢 Low | **Статус:** Resolved
- **Причина:** `--allow-unrelated-histories` + `reset --hard` + пересоздание веток → расхождение историй.
- **Решение:** Чистый `git clone` восстанавливает целостность.

### KI-009 — ERR_CONNECTION_RESET на сайтах с SSO
- **Приоритет:** 🟡 Medium | **Статус:** Documented
- **Причина:** Kinopoisk и подобные сайты требуют SSO-редирект, Chromium через прокси сбрасывает соединение.
- **Решение:** Использовать нейтральные сайты. Инъекция cookies — v1.1.

4.2. Ключевые архитектурные решения
#	Решение	Обоснование
1	Слоистость Data → Services → API	Чистое разделение; Services не зависит от API через AppVersionHolder
2	Гибридная БД (SqlServer/Sqlite/InMemory)	Не требует SQL Server от пользователя
3	CompositeAuditService	Аудит в БД и/или файл (JSONL) независимо
4	DI через конструктор везде	Тестируемость, отсутствие ServiceLocator
5	ToolRegistry + ITool	Новый инструмент = 1 класс + 1 строка регистрации
6	Func<ISubAgentService>	Разрыв DI-цикла SubAgent ↔ ToolRegistry
7	path в git/gh инструментах	Работа с несколькими репозиториями в workspace
8	GitContextValidationResult / GhContextValidationResult	Обход запрета out в async-методах
9	HttpClient.DefaultProxy + NO_PROXY	Единственный способ заставить ClientWebSocket использовать прокси с bypass loopback в .NET Core 3.1
10	HttpClientFactoryOptions.HttpMessageHandlerBuilderActions	Единственный способ передать прокси с credentials в IHttpClientFactory на 3.1
11	BrowserLocator	Автоопределение Edge/Chrome — не используем BrowserFetcher
12	--remote-allow-origins=*	Обход блокировки WebSocket в Chromium 111+
13	--proxy-bypass-list=<-loopback>	Обход прокси для WS-соединения с самим Chromium
14	Реалистичный User-Agent	Обход блокировки headless на сайтах
15	PuppeteerSharp 7.1.0	Исправления совместимости с современными Chromium
16	IStringLocalizer<SharedResources>	Единая точка локализации интерфейса
17	PendingAction + polling	Компромисс безопасности и UX без WebSocket
18	KNOWN_ISSUES.md	Реестр проблем и решений

## Контекст проекта

IIChatTools v1.0.2 — веб-приложение .NET Core 3.1 + EF Core,
предоставляющее локальной LLM (LM Studio, OpenAI-совместимый API на :8034)
40 инструментов: файловая система, выполнение кода, веб-поиск,
браузерная автоматизация (PuppeteerSharp + Edge/Chrome через прокси),
Git/GitHub, суб-агенты, утилиты.

Ключевые компоненты v1.0.2:
- 4 проекта: Data (netstandard2.1), Services (netstandard2.1), API (netcoreapp3.1), Tests
- Гибридная БД: SqlServer / Sqlite / InMemory (Database:Provider в конфиге)
- CompositeAuditService: БД + JSONL-файл (logs/audit/)
- Мультипользовательность: роли Admin/User, первый = Admin
- Подтверждения: PendingAction + polling /api/approvals/pending
- Суб-агенты: ISubAgentService + Func<ISubAgentService> (разрыв DI-цикла)
- Локализация: SharedResources.resx + IStringLocalizer<SharedResources>
- Аутентификация: cookie (Razor) + JWT (API)
- Git-инструменты: параметр `path` (каталог репо) + `filePath` (файл)
- GitHub-инструменты: параметр `path` для работы в подкаталогах
- Браузер: Edge + --remote-allow-origins=* + --proxy-bypass-list=<-loopback>
        + HttpClient.DefaultProxy для ClientWebSocket
- PuppeteerSharp 7.1.0
- Локальные библиотеки (bootstrap/jquery) в wwwroot/lib/

## Правила оформления (ОБЯЗАТЕЛЬНО)

1. Все комментарии и XML-документация — на русском
2. XML-doc обязателен для всех public классов/методов/свойств:
   <summary>, <param>, <returns>, <exception>
3. DI только через конструктор
4. Все I/O-методы — с суффиксом Async
5. Публичные члены — PascalCase, приватные поля — _camelCase
6. Контроллеры: try-catch → { success, data, message }
7. Сервисы: throw с осмысленным сообщением, не гасить стек
8. ILogger — технические логи; IAuditService — действия пользователей
9. Все пути — через PathHelper.TryGetSafeFullPath
10. CLI — только через ProcessStartInfo.ArgumentList
11. Версионирование — обновлять AppVersion.Current
12. Copyright: © 2026 RuChating (iilmchat) · IIChatTools v1.0.2
13. **Любая найденная проблема/ограничение → фиксируется в docs/KNOWN_ISSUES.md
    с номером KI-XXX, приоритетом (🔴/🟠/🟡/🟢), статусом и файлами.**
14. **Новые UI-строки — в оба .resx (RU + EN).** Тест
    LocalizationSyncTests проверит синхронность.
15. **Новый инструмент = 1 класс + 1 строка регистрации** в Startup.cs
    в соответствующей группе (RegisterFileSystemTools, etc.).

Часть 7. Как передать исходники в новый чат
Вариант A (рекомендую) — Git-репозиторий
Если у вас есть публичный Git-репозиторий (или self-hosted с публичным URL):

powershell
cd G:\AI\IIChatTools
git remote add origin https://github.com/iilmchat/IIChatTools.git
git push -u origin master --tags
В новом чате: «Изучи структуру проекта по https://github.com/...» — большинство современных чатов смогут открыть публичный репозиторий.

⚠️ Приватный репозиторий недоступен для большинства чатов. Для приватного используйте вариант B.

Вариант B — Zip-архив
powershell
cd G:\AI\IIChatTools
# Создаём архив, исключая bin/obj/Data/logs
$temp = "G:\AI\IIChatTools-export"
Remove-Item $temp -Recurse -Force -ErrorAction SilentlyContinue
robocopy "G:\AI\IIChatTools" $temp /E `
    /XD bin obj .git .vs .idea Data logs Workspace `
    /XF *.db *.db-shm *.db-wal *.user *.suo

Compress-Archive -Path "$temp\*" -DestinationPath "IIChatTools-v1.0.2-src.zip" -CompressionLevel Optimal
Remove-Item $temp -Recurse -Force
Размер архива: ~1–2 МБ без библиотек, ~5 МБ с ними.

Загрузите в облако (Google Drive, Яндекс.Диск, WeTransfer) — дайте ссылку новому чату. Если чат поддерживает загрузку файлов — загрузите zip напрямую.
