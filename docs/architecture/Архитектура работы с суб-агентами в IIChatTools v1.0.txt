Архитектура работы с суб-агентами в IIChatTools v1.0
Прежде чем перейти к коду, зафиксируем концепцию работы с суб-агентами — это ключевая часть проекта, обеспечивающая автономное выполнение сложных многошаговых задач.

Концепция
Суб-агент — это вторичный экземпляр LLM, работающий в изолированном цикле «запрос → выполнение инструментов → анализ → продолжение» в рамках одной задачи. Главный агент (внешняя LLM, работающая с IIChatTools) может делегировать суб-агенту целую задачу, не заботясь о деталях её выполнения.

Принципы работы
Изоляция контекста. Суб-агент получает свою историю сообщений. Главный агент видит только финальный результат.

Ограничение глубины. Суб-агент не может вызывать consult_secondary_agent (защита от бесконечной рекурсии). Инструмент физически исключается из списка tools, передаваемых суб-агенту.

Лимит шагов. По умолчанию 10 итераций, максимум 30. При достижении лимита суб-агент обязан завершить работу и вернуть промежуточный результат.

Персистентность. Каждая сессия суб-агента сохраняется в таблицу AgentState. При перезапуске приложения можно посмотреть, на каком шаге была остановлена задача.

Авто-сохранение. Если суб-агент в процессе работы генерировал код и использовал save_file — файлы уже на диске. Дополнительно сохраняется снимок истории в БД.

Авто-отладка (опционально). Если включён флаг autoDebug, после завершения задачи суб-агент передаётся агенту-рецензенту (та же LLM, но с другим системным промптом), который ищет ошибки и, при необходимости, возвращает задачу на доработку.

Мультипользовательность. Сессия суб-агента привязана к UserId — workspace, аудит и подтверждения изолированы.

Подтверждения. Инструменты, вызываемые суб-агентом, проходят ту же проверку IApprovalService. Если инструмент требует подтверждения, суб-агент получит ответ requiresApproval: true и должен сам решить, как действовать дальше (например, использовать альтернативный подход).

Схема цикла суб-агента
text
┌───────────────────────────────────────────────────────────────┐
│ Главный агент (внешняя LLM)                                    │
│   ↓ consult_secondary_agent(task, maxSteps)                    │
├───────────────────────────────────────────────────────────────┤
│ SubAgentService.ExecuteTaskAsync                               │
│   ↓ Создать AgentState в БД (CurrentStep = 0)                  │
│   ↓ Сформировать System+User сообщения                         │
│   ↓ Список tools (без consult_secondary_agent)                 │
│                                                                │
│   ┌─── Цикл до maxSteps ───────────────────────────────────┐  │
│   │  POST {LmStudio}/v1/chat/completions                    │  │
│   │  ← assistant: tool_calls ИЛИ финальный текст            │  │
│   │  Если tool_calls:                                       │  │
│   │    Для каждого: ToolRegistry.ExecuteAsync(...)          │  │
│   │    Добавить role:tool с результатом                     │  │
│   │    Обновить AgentState.CurrentStep++                    │  │
│   │  Если финальный текст → break                           │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                │
│   ↓ (опционально) Reviewer-цикл                                │
│   ↓ Сохранить финальный результат в AgentState.CodeSnapshotJson│
│   ↓ IsCompleted = true                                         │
├───────────────────────────────────────────────────────────────┤
│ Возврат SubAgentTaskResult                                     │
│   ↓ Главный агент получает краткий итог                        │
└───────────────────────────────────────────────────────────────┘
Компоненты
Компонент	Роль
ILmStudioClient	HTTP-клиент LM Studio (OpenAI-совместимый API /v1/chat/completions).
ISubAgentService	Оркестратор цикла суб-агента.
ConsultSecondaryAgentTool	Инструмент, через который главный агент вызывает суб-агента.
AgentState (БД)	Хранилище сессий суб-агента и снимков истории.
ToolRegistry	Единый реестр инструментов, используется и главным, и суб-агентом.
