6.2. Поток вызова инструмента
text
LLM → POST /api/tools/execute { toolName, arguments }
       │
       ▼
   ToolsController
       │
       ├─► 1. Проверка IToolRegistry.GetDescriptor
       │
       ├─► 2. Проверка IApprovalService.IsWhitelistedAsync
       │
       ├─► 3. Если RequiresApprovalByDefault && !whitelisted:
       │       ├─ Без approvalId → создать PendingAction,
       │       │   вернуть { requiresApproval: true, actionId }
       │       └─ С approvalId → проверить статус (Approved?)
       │
       ├─► 4. IWorkspaceResolver.GetWorkspacePathAsync(userId)
       │
       ├─► 5. IToolRegistry.ExecuteAsync(toolName, context, args)
       │       └─► ITool.ExecuteAsync(context, args)
       │
       ├─► 6. IAuditService.LogActionAsync (Success/Error, Duration)
       │
       └─► 7. Вернуть { success, data, message }
6.3. Поток суб-агента
text
Главный LLM → consult_secondary_agent(task, maxSteps, autoDebug)
       │
       ▼
   ConsultSecondaryAgentTool
       │
       ▼
   SubAgentService.ExecuteTaskAsync
       │
       ├─► 1. Создать AgentState в БД (CurrentStep = 0)
       │
       ├─► 2. Сформировать system + user messages
       │
       ├─► 3. Список tools без consult_secondary_agent
       │
       ├─► 4. Цикл до maxSteps:
       │       ├─ POST LM Studio /v1/chat/completions
       │       ├─ Если tool_calls → выполнить каждый через ToolRegistry
       │       │   (с той же проверкой approval и безопасности)
       │       ├─ Обновить AgentState.CurrentStep
       │       └─ Если финальный текст → break
       │
       ├─► 5. Если autoDebug → RunReviewerAsync (агент-рецензент)
       │
       ├─► 6. Сохранить снимок в AgentState.CodeSnapshotJson
       │
       └─► 7. Вернуть SubAgentTaskResult главному агенту
6.4. Принципы архитектуры
Принцип	Реализация
Слоистость	Data → Services → API. Services не зависит от API (разрыв через AppVersionHolder).
Расширяемость	Новый инструмент = 1 класс, реализующий ITool + 1 строка регистрации в Startup.cs.
DI через конструктор	Все сервисы и инструменты внедряются через конструктор. IServiceProvider не используется напрямую.
Cross-cutting	ILogger (технические события), IAuditService (действия пользователей), IApprovalService (подтверждения).
Безопасность	PathHelper.TryGetSafeFullPath, ProcessStartInfo.ArgumentList, whitelist команд, лимиты, таймауты, TTL-сессии.
Async/Await	Все I/O-методы с суффиксом Async. CancellationToken прокидывается через всю цепочку.
Локализация	SharedResources.resx + SharedResources.ru.resx, синхронизация проверяется тестом LocalizationSyncTests.
Версионирование	AppVersion.Current (API) + AppVersionHolder (Services).
Мультипользовательность	Изоляция workspace ({RootPath}/users/{userId}), проверка владельца ресурсов.
Подтверждения	Все критичные инструменты генерируют PendingAction; клиент опрашивает /api/approvals/pending.
ES-модули	Клиентский JS полностью модульный, точка входа main.js, namespace window.IIChatTools.
